# Engineering Standards

These are binding for all new code, not aspirational. Every document
below is written from conventions already followed consistently across
this codebase — not invented rules waiting to be adopted.

| Document | Covers |
|---|---|
| [`coding-standards.md`](./coding-standards.md) | Naming, file organization, hook shape |
| [`api-standards.md`](./api-standards.md) | Route handler convention, auth, response shape |
| [`testing-standards.md`](./testing-standards.md) | What exists today, what's expected going forward |
| [`branch-strategy.md`](./branch-strategy.md) | Branch naming and flow |
| [`commit-convention.md`](./commit-convention.md) | Commit message format |
| [`versioning.md`](./versioning.md) | Semantic Versioning application |

See `docs/standards/engineering-standards.md` for the one-page index that
ties all six together, if you want the overview before the detail.
